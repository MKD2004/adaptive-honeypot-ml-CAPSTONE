### 1.4 Plumbing

- **`src/services/api.js`**: reads plus writes (POST/DELETE blacklist/whitelist,
  RESET, threat-intel refresh). Errors are told apart: unreachable, timeout,
  HTTP error, or bad JSON.
- **`src/hooks/useApiResource.js`**: optional polling. Background refreshes
  don't flash a spinner and never overlap.
- **`vite.config.js`**: `/api/*` is proxied to `http://localhost:5000`
  (`VITE_API_PROXY_TARGET`), so the dashboard works from another laptop on the
  LAN. When the API is down, the proxy returns a JSON marker so the UI says
  "unreachable" instead of "error". Charts and React are split into their own
  bundles, which removed the 500 kB build warning.
- **Top bar**: live API status, whether MT3 is loaded, routing mode, and the
  `ssh root@<lan-ip> -p 8080` command peers type.
- **`src/lib/schema.js`**: real-data flags corrected from 22 classes to **13**
  (DECISIONS.md 2026-08-28). Interaction-level table added, mirroring
  `configurator.py`.
- **`.eslintrc.cjs`**: ignores `dist/`. Previously `npm run lint` after a build
  reported ~400 false errors.
- **`.env.example`, `README.md`**: rewritten for the proxy and the new pages.

## 2. Threat-intelligence layer

### 2.1 What was wrong

| Problem | Effect |
|---|---|
| EPSS URL `api.first.org/data/1.0/epss` now returns **404 for every CVE** (even CVE-2021-44228); the current endpoint is `/data/v1/epss` | Every request failed and `simulate_epss()` quietly filled in random Beta(seed 42) scores. Live test before the fix: **0 / 517 real** |
| `cve_intelligence/data/trending_profiles.json` is a June 2026 snapshot, and nothing regenerated it at runtime | The honeypot's CVE overlay never changed |
| MT3's KEV list came from the extractor's `get_kev_set()`, which returns `ti_cache.json` forever once cached | Startup banner showed 1,675 KEV entries; the live catalog had 1,766 |
| `ATTACK_TYPE_PHASES` in the configurator used names the classifier never emits (`"remote code execution"`, `"deserialization"`); brute force, file inclusion, SSRF, XXE etc. were missing | On live data **no CVE overlay ever matched**. The June snapshot only "worked" because its 3 attack types happened to match |

### 2.2 Changes

| File | Change |
|---|---|
| `cve_intelligence/config.py` | `EPSS_API_URL` → `/data/v1/epss`. Added `ALLOW_SIMULATED_EPSS` (env `CVE_ALLOW_SIMULATED_EPSS=1`, **off** by default) and `REFRESH_INTERVAL_HOURS` (env `CVE_REFRESH_HOURS`, default 6) |
| `cve_intelligence/analyzers.py` | New `fetch_epss_details()` (score + percentile). `enrich_epss()` adds `epss_percentile` and `epss_source` (`first.org` / `unscored` / `simulated`). Unscored CVEs get 0.0, not a random number. Logs an ERROR if every EPSS request fails |
| `cve_intelligence/config_generator.py` | Profiles include `epss_percentile`, `epss_source`. JSON written atomically (tmp + replace) |
| `cve_intelligence/pipeline.py` | Records what each source returned. Writes `trending_profiles.meta.json` (fetch time, CVE source, KEV catalog size, EPSS counts, trending basis, source URLs) |
| `cve_intelligence/refresher.py` **(new)** | Background thread: runs the pipeline at startup if live intel is missing or stale, then every 6 h. Writes to `cve_intelligence/data/live/` (gitignored). A failed run keeps the last good data. `python -m cve_intelligence.refresher` does a one-off refresh |
| `adaptive_honeypot/configurator.py` | Prefers `data/live/trending_profiles.json` over the snapshot. Re-reads it when the file changes (no restart). `ATTACK_TYPE_PHASES` aligned with the classifier's real labels. App-server/PHP profiles no longer put e.g. a Tomcat banner on the SSH honeypot. `cve_profile` now records `epss_source`, `kev_date_added`, `intel_source` (live / snapshot) |
| `traffic_gateway/feature_bridge.py` | `ThreatIntelCache` fetches KEV from cisa.gov (`CISAClient`) and EPSS from FIRST v1, refreshed hourly. `ti_cache.json` is only an offline fallback. Reports `kev_source` |
| `traffic_gateway/post_session_pipeline.py` | Exposes threat-intel status in startup info and `stats()` |
| `traffic_gateway/run_pipeline.py` | Starts the refresher. New `--no-intel-refresh` flag. Banner shows KEV source and CVE-intel status |
| `traffic_gateway/api.py` | New `GET /api/threat-intel` and `POST /api/threat-intel/refresh`. Standalone `traffic_gateway.api` also starts the refresher (`--no-intel-refresh` to disable) |
| `.gitignore` | Added `cve_intelligence/data/live/` |
| Frontend | Threat Intelligence panel on the Adaptive Honeypot page. Active-config card says whether its CVE overlay came from live or snapshot intel |
